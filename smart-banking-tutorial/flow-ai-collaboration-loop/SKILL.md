# AI 协作闭环（分析→生成→运行→调试）

## R — 原文引用

> "与AI高效协作有一个隐藏的'节奏感'，我们总结为四步闭环：**分析需求 → 生成方案 → 运行验证 → 调试修正**，然后回到分析。掌握这个节奏，你不会在AI出错时慌乱，也不会在没有验证时就轻信AI的输出。"
> — 《智慧银行实验教程》ch02 §2.6.3

## I — 方法论骨架

四步闭环（每步都有进入/退出条件）：

```
┌─────────────────────────────────────────────┐
│                                             ▼
分析需求  →  生成方案  →  运行验证  →  调试修正
│                                       │
└───────────────────────────────────────┘
（每轮闭环使方案更接近正确，通常2-5轮收敛）
```

| 步骤 | AI做的事 | 人做的事 | 进入条件 | 退出条件 |
|---|---|---|---|---|
| **分析** | 拆解需求、列出方案 | 确认理解对、补背景 | 收到任务 | 双方对"要解决什么"达成一致 |
| **生成** | 写代码/文本/方案 | 看一眼大方向对不对 | 分析完成 | 产出可运行/可验证的初稿 |
| **运行** | （辅助）执行、跑测试 | 看结果、记现象 | 生成了初稿 | 拿到明确的"成功"或"失败"信号 |
| **调试** | 定位bug、给修复 | 判断修复方向对不对 | 运行失败 | 找到根因，回到生成 |

**节奏的三个原则**：
1. **不跳步**：分析没做透就生成 = 注定要返工；生成没运行就交付 = 在赌运气
2. **不恋战**：调试超过3轮没进展 → 退回分析重新拆问题（通常是分析阶段漏了什么）
3. **留痕迹**：每轮的"现象、假设、修复"要记下来——AI的上下文会丢，人也会忘

## A1 — 书中案例

**贪吃蛇游戏开发实验**（ch02 §2.6.3）：
- 第1轮：分析"画蛇+移动+吃食物" → 生成Pygame代码 → 运行发现"蛇不动" → 调试发现事件循环写错
- 第2轮：分析"蛇会动了但穿墙" → 生成边界检测 → 运行发现"撞墙后游戏不结束" → 调试发现没写game over
- 第3轮：分析"完整游戏循环" → 生成死亡判定+计分 → 运行通过

**Excel合并实验**：
- 第1轮：分析"多个Excel合并成一个" → 生成pandas脚本 → 运行报错"编码问题" → 调试加encoding参数
- 第2轮：成功

**核心观察**：三个实验都经历了2-5轮闭环，没有任何一次是"一次过"。

## A2 — 未来触发场景

**应触发**：
- "AI生成的代码报错了怎么办"
- "怎么跟AI来回改东西效率高"
- "AI协作的节奏/流程是什么"
- "什么时候该放弃AI给的方案重写"
- "AI卡住了怎么破"
- "怎么避免和AI无限改下去"

**不应触发**（诱饵）：
- 单纯问"怎么写提示词" → 用meta-rteii-prompt-principles
- 单纯问"用什么AI模式" → 用meta-ai-collaboration-four-modes
- 问"具体某个bug怎么修" → 具体技术问题

## E — 可执行步骤

1. **进入分析**（5-15分钟）：让AI用自己的话复述任务，列出2-3种方案+权衡——人确认理解对了再往下
2. **进入生成**：要求AI"先给最小可运行版本，不要加多余功能"——避免一上来就过度设计
3. **进入运行**：立刻跑——别等"看起来完美"才跑。看现象时只记事实（"蛇穿了墙"），别记判断（"边界逻辑错了"，这可能错）
4. **进入调试**（如果失败）：
   - 让AI先复述"这个错误说明什么"，列出3个可能原因
   - 人判断哪个最可能，优先查那个
   - 修复后立刻重跑验证
5. **退回分析**（如果3轮没修好）：一定是分析阶段漏了什么。停下来问"我们一开始假设了什么？这个假设对吗？"
6. **退出闭环**：成功标志 = 能跑通 + 能解释为什么 + 能复现（再跑一次也对）

## B — 边界与盲点

**不适用**：
- 极简任务（如翻译一句话）——不需要四步，直接生成+人看一眼即可
- 创意发散（如头脑风暴）——没有"对错"，调试闭环不适用
- 探索性研究（如数据探索）——闭环目标不明确，应先做meta-bmad-five-phases的B阶段

**作者盲点**：书中对"什么时候该换AI/换人"讨论不足。实践中：
- 同一个AI连续3轮失败 → 换一个AI（不同模型）试试，可能是模型能力瓶颈
- 人连续2小时理不清 → 找另一个人讨论，可能是认知盲区
- 永远不要在同一个错误上磨超过1天——时间盒到了就换思路
