# 6节点 Skill 流水线（文献→数据→清洗→回归→图表→论文）

## R — 原文引用

> "金融实证研究的完整流程可以抽象为6个标准节点——**文献调研 → 数据获取 → 数据清洗 → 回归建模 → 可视化 → 论文撰写**。我们把每个节点封装为可复用的Skill，配合反馈环，使整个研究过程像流水线一样可执行、可复现、可迭代。"
> — 《智慧银行实验教程》ch06 §6.1

## I — 方法论骨架

### 主流水线（6节点线性推进）

```
[1.文献] → [2.数据] → [3.清洗] → [4.回归] → [5.图表] → [6.论文]
   ▲                                                    │
   └──────────────── 反馈环（每节点都可能回退）────────┘
```

### 各节点的输入/输出/Skill候选

| 节点 | 输入 | 输出 | 关键 Skill 候选 |
|---|---|---|---|
| **1. 文献** | 研究问题 | 文献综述+研究缺口 | find-papers、summarize-paper、gap-analysis |
| **2. 数据** | 变量清单 | 原始数据集 | tushare-skill、wind-skill、csmar-skill、scrape-data |
| **3. 清洗** | 原始数据 | 分析用数据 | missing-value、outlier、merge-panel、winsorize |
| **4. 回归** | 清洗后数据+模型设定 | 回归结果表 | ols、panel-fe、iv、did、mediation |
| **5. 图表** | 回归结果 | 论文级图表 | coefficient-plot、event-study、scatter-fit |
| **6. 论文** | 全部产出 | 论文初稿 | intro-writer、results-section、discussion |

### 反馈环（关键设计）

不是一条直线走到底，而是每个节点都可能触发回退：
- **节点4失败**（回归不显著）→ 回到节点1（重新查文献找新视角）或节点2（换数据）
- **节点5不满意**（图表讲不清故事）→ 回到节点4（换模型设定）
- **节点6写不出来** → 回到节点1（故事没讲圆，缺理论支撑）

## A1 — 书中案例

**"货币政策对银行风险承担的影响"研究**（ch06 §6.2 完整案例）：
- 节点1：读30篇文献 → 发现缺口"少有人做城商行vs农商行对比"
- 节点2：用Tushare Skill拉2010-2023年100家银行财报+宏观货币政策数据
- 节点3：缺失值填补+缩尾+生成风险承担指标（Z-score、不良率）
- 节点4：双向固定效应面板回归 → 货币政策系数显著但符号和文献相反
- **反馈**：回到节点1重读文献 → 发现没控制"银行规模" → 回节点3加控制变量
- 节点4重跑：系数方向正确，显著
- 节点5：画event-study图+异质性对比图
- 节点6：生成论文初稿，3天完成

## A2 — 未来触发场景

**应触发**：
- "怎么做金融实证研究"
- "实证研究的流程/pipeline"
- "从数据到论文怎么做"
- "量化研究怎么组织"
- "研究项目该怎么拆分Skill"
- "为什么我的实证跑不出结果"

**不应触发**（诱饵）：
- 单纯问"OLS怎么做" → 统计学知识
- 单纯问"某只股票数据分析" → 具体分析任务
- 问"怎么写文献综述" → 用节点1专门的skill

## E — 可执行步骤

1. **画节点地图**：把你的研究问题分解到6节点——每个节点写下"输入是什么、输出是什么、用什么Skill"
2. **先跑通最小主流水线**：每节点用最简单的Skill跑一遍，不求完美，先验证整条链路能通（哪怕结果不显著）
3. **审视反馈环**：问自己"如果节点4结果不对，我要回退到哪？"——预先想好回退路径
4. **逐节点深化**：从最关键的节点（通常是节点3清洗和节点4回归）开始，换成更专业的Skill
5. **记录每轮迭代**：建一个 `research-log.md`，记下"第N轮：改了什么、为什么改、结果如何"——避免重复掉坑
6. **节点6不要拖**：很多人卡在"结果不够好不敢写"——其实边写边发现故事讲不通，反而能倒逼前面的节点优化

## B — 边界与盲点

**不适用**：
- 纯理论研究（没有数据/回归）——只需节点1+节点6
- 案例研究（单一深度案例）——不走流水线
- 实验研究（如实验室实验）——节点2换成"实验设计"

**作者盲点**：书中对"节点之间的数据格式对齐"讨论不足。实践中：
- 节点2到节点3：原始数据常有"宽表/长表"格式冲突，建议统一用长表
- 节点4到节点5：回归结果对象（如statsmodels的RegressionResults）要序列化为标准json，否则画图Skill读不懂
- 节点5到节点6：图表文件命名规范要统一（fig01.png、fig02.png），否则论文Skill引用会乱
